# Rule Coverage

For focused command selection and the distinction between deterministic,
authoring, conditional, and advisory work, start with
[enforced engineering rules](template/enforced-engineering-rules.md). This is
the detailed rule-to-mechanism map, not a per-task full-verification checklist.

Every stated rule maps to the mechanism that enforces it. Enforcement tiers,
strongest first:

- **mechanical** — a tool measures the code itself and fails the build.
- **ai-judge** — an advisory LLM review of the diff against a pinned rubric. It
  reports findings but is not a blocking CI authority.
- **pin-only** — a static compatibility requirement asserts that exact bytes
  remain where they are an external contract. It protects shape; it does not
  measure behavior.
- **review** — humans/agents via the PR template checklist and ordinary review.
  Weakest tier; anything resting here is a porting candidate.

## Process and CI integrity

| Rule                                 | Enforcement                                                                                                                                                                                                                                                                    |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| CI gate structure cannot be weakened | mechanical-ish: secretless Woodpecker `trusted-ci-policy` step runs `check:ci-completeness` + `check:config-drift` pins before any credentialed job                                                                                                                            |
| Canonical gate names stay stable     | mechanical-ish: package scripts own command bodies; `check:ci-completeness` validates Woodpecker and Lefthook wiring                                                                                                                                                           |
| Fast local admission                 | mechanical: Lefthook pre-commit runs staged formatting and the staged ESLint debt ratchet; broad verification runs once in Woodpecker                                                                                                                                          |
| PR verification has one authority    | mechanical: plain GitHub branches and PRs receive their sole blocking verdict from Woodpecker                                                                                                                                                                                  |
| Docs stay navigable                  | pin-only: `check:docs-freshness`                                                                                                                                                                                                                                               |
| Hosted app works                     | mechanical: Playwright smoke + accessibility + visual baselines (`smoke:hosted:*`), static build smoke; the smoke suite asserts the Saas UI shell renders and the workflow card shows either a configured live Convex stream or an honest fake-safe/unseeded/unavailable state |
| Debt is visible                      | pin-only: `check:debt`; review: suppression ban in PR template                                                                                                                                                                                                                 |
