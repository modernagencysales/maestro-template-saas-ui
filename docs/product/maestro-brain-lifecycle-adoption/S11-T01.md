**Owner:** S11-T01

## Durable resources

`servicePrincipals` stores one organization/workspace/Brain binding, viewer role
ceiling, lifecycle status and generation, creator, creation time, and revocation
time. `apiKeys` stores only the secret hash, display prefix, exact principal and
Brain binding, scopes, principal generation, expiry/revocation/use metadata, and
tenant indexes. Domain functions cover display-once creation, metadata-only
listing, constant-time verification, revocation, and rotation.

## Lifecycle behavior

Keys and principals move from `active` to terminal `revoked | expired`.
Verification requires an active exact service principal, `brain:read` for every
Brain key, the requested optional `brain:ask` scope, a viewer ceiling, an
unexpired key, and matching principal generation. Rotation revokes the old key,
creates a new secret, and increments the existing principal generation so stale
keys fail closed.

## Compatibility and rollback

Legacy workspace-key fields and scopes remain readable through optional Brain
fields, but legacy/admin keys cannot authorize a Brain scope without an exact
service principal. Rollback revokes the new key or principal and retains only
hash/prefix metadata. The earlier fail-closed Confect CRUD fixture was removed
rather than exposed as a working endpoint; database-backed CRUD capability
promotion remains explicit acceptance work.
